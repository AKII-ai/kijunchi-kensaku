# 出典を足す（API に無い告示・通知）

告示・条例・通知は e-Gov 法令API に無いので、ページ（または PDF）を手元に保存し、そこから読みます。
**正本は保存したファイル**です。メモには「どこを読むか」だけを書き、数値は書きません。

## 置き場所

| 場所 | 役割 | 手で書くか |
|---|---|---|
| `sources/urls.md` | 名前・URL・種類・メモのファイル名の台帳 | 書く |
| `sources/notes/{名前}.md` | その出典の整理メモ。1出典1枚 | 書く |
| `sources/saved/{名前}_{入手日}.{拡張子}` | 保存したページ（正本） | 保存するだけ |
| `sources/read/{名前}.json` | 保存したページの読み取り結果 | 書かない（`npm run sources:read` が作る） |
| `sources/read/_check.json` | 最後の URL の確認結果 | 書かない（`npm run sources:check` が作る） |
| `sources/read/_changes.json` | これまでの「更新」「移転」の記録（消さない） | 書かない（同上） |
| `sources/read/_previous/{名前}_{日付}.json` | 「更新あり」のとき、読み直す前の読み取り結果。画面の「更新（前の値）」に使う | 書かない（同上） |

PDF の表を読むのに Python と PyMuPDF（`pip install pymupdf`）を使います。

## 足し方

1. `sources/urls.md` に1行足す。名前、URL、種類を書き、メモの列は空のままにする。
2. その URL を開き、ページ（または PDF）を `sources/saved/{名前}_{入手日}.html`（`.pdf`）として保存する。
   本文ページに表が無く PDF へのリンクだけのときは、PDF を保存して1つ目にし、本文ページは控えとして2つ目に保存する。
3. [templates/source-note.md](../templates/source-note.md) を `sources/notes/{名前}.md` にコピーし、上の項目と「どこを読むか」を埋める。数値は書かない。
4. 台帳のメモ列に、そのファイル名を書く。
5. アプリにつなぐときは、メモに `- 読み方:` と「使う表」「項目名の列」「基準の文言の列」（n番目・n列目）を書き、`npm run sources:read` を流す。
   `sources/read/{名前}.json` に行が取れたことを確かめてから、[主要基準一覧を変える.md](主要基準一覧を変える.md) の手順で列や行につなぐ。

- ページが表ではなく本文だけのときは、メモの「表が無いとき」を埋めます。
- 同じ出典に表が複数あるときは、使う表を書き、使わない表には理由を1行書きます（例: 水質環境基準は別表1だけ。別表2は混ぜない）。
- 1つの PDF から複数の表を使うときは、表ごとに別の出典（別のメモ）にし、`pdf-section-table` の「使う見出し」で分けます。
  見出しは空白を除いて行全体が同じなら一致します。「別紙１*」のように * で終えると、その文字で始まる行に一致します。
- 改正の全文が公開されていないときは、改正の概要を別の出典にし、主要基準一覧の列で本体より左に書きます（地下浸透基準の令和6年改正がこれ）。

## 読み方

`- 読み方:` に書ける名前は、`tools/sources.py` の `READERS` にあるものです。

| 読み方 | 読むもの | メモで使う欄 |
|---|---|---|
| `html-table` | HTML の `<table>` | 使う表、項目名の列、基準の文言の列 |
| `pdf-table` | PDF の罫線の表。ページをまたぐ1つの表として読み、ページの境目で割れた行はつなぐ。小さい字のルビは捨てる | 使う表、項目名の列、基準の文言の列 |
| `amendment` | 改正の概要の「「物質」の別表下欄に掲げる値を…に改める」 | なし |
| `pdf-section-table` | PDF の中の、見出し「使う見出し」の後から「次の見出し」の前までにある表。1つの PDF に同じ形の表がいくつもあるとき（要監視項目の公共用水域と地下水、別添の別紙1と別紙2など）に使う | 使う見出し、次の見出し、項目名の列、基準の文言の列 |

新しい形のページ（たとえば CSV や、表でない本文）を読むときは、`tools/sources.py` に `read_xxx(path, note)` を1つ書き、`READERS` に名前を足します。
返すのは `[{ "item": 項目名, "value_raw": 基準の文言 }]` の並びです。ほかのところは直しません。

## 更新の確かめ方

`npm run sources:check` で、URL が書いてあるメモすべて（値を読まず根拠にだけ使う出典も含む）の URL を開き、前回保存したファイルと比べます。

| 結果 | 判定 | 日付 | 画面 |
|---|---|---|---|
| 開けない | ページが見つからない、つながらない、中身が空、URL が古い | 入手日も前回確認日も変えない | 表の上に赤字で出す。表の中は「参照不可」（列の出典なら列見出しに1つ、別の出典から取ったセル・行の注の根拠ならそのセル・物質名に）。値は前回保存したページのまま |
| 移転 | 開くと別の URL に転送された（中身は前回と同じ） | 転送先を新しい URL とし、台帳・メモ・主要基準一覧の指定の古い URL を書き換える。前回確認日をその日にする | 表の上に「新しい URL にしました」と出す |
| 更新あり | 今の本文が、前回保存したファイルと違う | 新しいページを保存し、入手日と前回確認日をその日にする | 出典の名前と「前回保存したページと違う」を出す。数値の差分は書かない |
| 同じ | 前回保存と同じ | 前回確認日だけをその日にする | 何も出さない |

**GitHub で毎週自動で確かめます**（`.github/workflows/sources-check.yml`、毎週月曜 6:00）。変化があればコミットして公開サイトを作り直します。
読み直しに失敗したときは止まり、公開しません（GitHub から失敗の通知が届きます）。GitHub の Actions の画面から手で動かすこともできます。

「更新あり」「移転」があった出典は、続けて自動で読み直します（`sources/read/*.json`）。そのあと `npm run summary` を流し、コミットして push すると公開サイトにも反映されます。
転送されて中身も変わっていたときは「更新あり」になり、URL の書き換えと新しいページの保存の両方を行います。何の数値が変わったかは記憶で書きません。正本は新しく保存したページです。
HTML は本文（`<main>`）の文字、PDF は全ページの文字で比べるので、ページの飾りが変わっただけでは「更新あり」になりにくくしています。
