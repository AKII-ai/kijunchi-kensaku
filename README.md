# 基準値検索ver1.0

法令の基準値を、e-Gov 法令API v2 の条文から表にして見るブラウザアプリです。

公開ページ: https://akii-ai.github.io/kijunchi-kensaku/
値の正本は、法令はそのとき API が返した条文、告示（環境基準など）は手元に保存した環境省のページです。

## 起動のしかた

```
npm install
npm run dev
```

表示された `http://localhost:5173/` を開きます。
ブラウザから API へ直接アクセスすると CORS で止まるので、開発サーバが `/egov` を
`https://laws.e-gov.go.jp/api/2` へ転送します（`vite.config.js`）。ログインは不要です。

公開用に固めるときは `npm run build`、その確認は `npm run preview` です。

## できること

- **主要基準一覧**（最初の画面の一番上）。物質×12基準（土壌・地下水・水質の環境基準、水道水質基準、排水基準、
  地下浸透、土壌汚染対策法の4基準、廃棄物埋立判定基準、水底土砂基準）の1枚の表。
  法令の列は開くたびに API の現行版から、告示の列は `sources/read/` の読み取り結果から埋めます。
  同じ表を `docs/主要基準一覧.md` にも書き出せます（`npm run summary`）。
- 法令名で検索する。検索欄の文字で `laws` を呼びます。例のボタンは「大気」「土壌」「地下水」。
- 「よく使うもの」から選ぶ。土壌汚染対策法・水質汚濁防止法・下水道法の法律／政令／省令です。
- 選んだ法令の基準値を、施行期間ごとの表で見る。新しい期間が上です。
  1つ前の収録版と文言が違うセルは薄い黄色、変更前は同じセルの赤いかっこ書きです。
- 土壌汚染対策法施行規則（`414M60001000029`）だけ、`src/layouts/` の指定で
  物質×4基準（土壌溶出量・土壌含有量・地下水・第二溶出量）の横並びになります。
  ほかの法令は、抜いた順の縦の表です。
- 基準値の行が1件以上取れた法令のカードは緑になります。
- **ダウンロード（zip）**。「ダウンロード（Excel・Markdown／zip）」ボタンで保存します。
  - 開いた法令: Excel 1冊（施行期間ごとのシート。新しい期間が最初）と、施行期間ごとの Markdown（`markdown/01_施行…_現行.md` から古い順）。
    「変更コメントあり」と「コメントなし」を選べます。コメントありは、変わったセルを Excel では薄い黄色と赤いかっこ書き、
    Markdown では太字とかっこ書きにし、その期間に無くなった行を打ち消し線で残します。コメントなしは印を付けず、その期間の基準値だけです。
  - 主要基準一覧: Excel（一覧と「注記と出典」の2シート）と Markdown 1つ。Markdown は `npm run summary` と同じ書き方です。
  - Excel を作る exceljs は大きいので、ボタンを押したときだけ読み込みます。

条文からの抜き出しは4種類です（`src/extract/extract.js`）。

| 読み方 | 対象 |
|---|---|
| 別表 | `AppdxTable` |
| 号列記 | `Item` の `Column`。本文に `src/extract/unit_hints.txt` の語がある条だけ |
| 条文の中の表 | `AppdxTable` の外側にある `Table` |
| 地の文 | 「検出されること」「検出されないこと」で基準を定めている条。1条につき1行 |

号列記の対象にする言い回しを増やすときは、`src/extract/unit_hints.txt` だけを直します（[docs/法令を足す.md](docs/法令を足す.md)）。

## 告示（API に無い出典）の更新

告示は API に無いので、環境省のページを `sources/saved/` に保存し、そこから読みます。
PDF の表を読むのに Python と PyMuPDF（`pip install pymupdf`）を使います。

```
npm run sources:check   URL を開き、保存したページと比べる（同じ／更新あり／開けない）
npm run sources:read    保存したページから項目と文言を読み、sources/read/*.json を作り直す
npm run summary         docs/主要基準一覧.md を作り直す（npm run summary -- 書き出し先.md で場所を変えられる）
```

- `sources:check` で「更新あり」なら、新しいページを保存し、メモの入手日を書き換えます。続けて `sources:read` を流します。
  結果は `sources/read/_check.json` に残り、画面の主要基準一覧の上に「更新あり」「開けない」が出ます。
- どの出典のどの表・列を読むかは、`sources/notes/{名前}.md` の「読み方」「使う表」「項目名の列」「基準の文言の列」です。
- `sources/read/*.json` はスクリプトが作る写しです。手で直しません。
- 主要基準一覧の物質と列は `src/summary/rows.md` と `src/summary/columns.md`。どちらも数値は書きません。
  rows.md のセルは、その列の出典での呼び方（条文・告示の表記のまま）です。見つからない呼び方は画面に赤字で出ます。

地下浸透の値（平成元年環境庁告示第39号の備考欄）は、環境省掲載の全文が平成24年改正までです。
令和6年改正（六価クロム化合物）は改正の概要 PDF から読み、上書きしています。

## まだできないこと

- 水道の要検討項目を表に出すこと（現行の一覧を公式資料で確かめられていない）

過去に遡れるのは、API が返す版までです。多くの法令で、おおむね 2017 年より前の版は
返りません。それより古い基準は、官報など原典に当たります。

## フォルダ

```
src/
  main.js          画面の入口
  api/egov.js      e-Gov の取得だけ
  extract/         4種類の抜き出しと、並びファイルの読み方
    unit_hints.txt 号列記の対象にする言い回し。1行1語
  layouts/         法令ごとの並び。ファイル名は法令ID.md。値は書かない
  summary/         主要基準一覧。columns.md（列と出典）、rows.md（物質と呼び方）、summary.js（組み立て）、markdown.js（Markdown の書き方）
  export/          ダウンロード（Excel・Markdown・zip）
  ui/              画面
sources/
  urls.md          API に無い出典の URL 台帳
  notes/           入手したあとの整理メモ。1出典につき1ファイル
  saved/           保存したページ（正本）。ファイル名は 名前_入手日
  read/            保存したページの読み取り結果（tools/sources.py が作る）
tools/
  sources.py       保存したページの読み取りと、URL の確認
  summary.mjs      docs/主要基準一覧.md の書き出し
templates/         コピーして使うひな形（layout.md: 法令の並び、source-note.md: 出典の整理メモ）
docs/              決まりごとと足し方。主要基準一覧.md は npm run summary が作る
_local/            手元だけに置くもの（.gitignore で GitHub に上げない）。最初の作業指示など。アプリは使わない
```

## 直す・広げるとき

決まりごとと足し方は [docs/README.md](docs/README.md) にまとめています。どれも「1つ足すときは、この場所に1つ足す」形です。

| やりたいこと | 読むところ |
|---|---|
| 法令を「よく使うもの」に出す・横並びにする・抜き出しの言い回しを増やす | [docs/法令を足す.md](docs/法令を足す.md) |
| 告示・通知の出典を足す・更新を確かめる・新しい形のページを読む | [docs/出典を足す.md](docs/出典を足す.md) |
| 主要基準一覧に列・物質を足す | [docs/主要基準一覧を変える.md](docs/主要基準一覧を変える.md) |
| 画面の色・ボタン・ダウンロードの意味 | [docs/画面.md](docs/画面.md) |
